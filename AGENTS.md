# Working on the status UI

- This project incorporates BetterStatusPage. Consult [UPSTREAM.md](UPSTREAM.md), the upstream source, and the demo when working on UI parity. Prefer extracting and reusing upstream components and behavior. If extraction is unsuitable, duplication or an implementation inspired by upstream is acceptable; document the reason and preserve attribution and license notices.
- The Cloudflare admin intentionally displays unsupported upstream navigation items and monitor editor sections as disabled visual reminders. Disabled controls must remain visibly unavailable, non-interactive, and accessible; they must not submit settings or imply that an unsupported backend exists.
- Enable a placeholder only when its applicable Cloudflare API, persistence, permissions, and runtime behavior work end to end. Preserve working controls, Cloudflare Access authorization, and read-only treatment of Gatus-managed monitors. Update capability gating and tests when support changes.
- The Cloudflare monitor editor exposes Checks, Auth, Request, Alerts, and Depends On to administrators and Tags to operators and administrators, when the relevant capabilities are available. Incident and Latency are placeholders; see GitHub issues #4–#12 for the remaining work. The upstream Node profile keeps its existing behavior.

## Branch preview verification

- For branch-specific staging verification, push a same-repository branch containing current `main` and its CI workflow. `feat/**` and `fix/**` use shared Dev, `stage/**` uses shared Stage, and `schema/**` uses a dedicated schema-validation database. `codex/**` branches do not deploy automatically.
- After CI passes, check the **Branch previews** deploy-job summary for the URL, selector, environment, and exact tested commit before testing. For browser setup and troubleshooting, follow [the preview browser guide](docs/staging-preview-browser.md). Launch `node scripts/preview-browser.mjs https://status.sow.foo/ <selector>` after installing dependencies and Playwright Chromium, then sign in through Cloudflare Access.
- Send `X-Status-Preview: <selector>` with every API request as well as normal Access authentication. The browser launcher supplies it for navigation, assets, and APIs. Requests without a selector reach baseline staging, not the branch preview.
- Dev and Stage databases are shared within their respective environments: coordinate writes, identify test records with the selector, and leave test monitors disabled. Shared-database feature migrations must already be approved and applied; use `schema/**` to test new migrations in isolation.
- Dev and schema databases start without the staging Gatus catalog, and new Dev users default to viewer. Subscriber scheduling and email readiness are disabled in dynamic previews, and preview probes have no cron. Use an isolated mock or fixture when a test requires a simulated backend response.
- Deleting an eligible branch triggers preview retirement and, after a one-hour drain, cleanup when reconciliation is enabled. The manual staging-slot workflow remains separate.

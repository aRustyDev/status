# Private Gateway Forward bridge

This experimental Worker exposes the named `GatewayMiddleware` entrypoint for a private WARP hostname. It has no public `fetch` entrypoint. It checks a Cloudflare Access assertion or application cookie against the configured issuer and audience, requires a subject, email and unexpired token, and matches the email to the Gateway identity. The verified assertion is passed to the `FALLBACK` service binding, which targets the independently protected static-fallback Worker; that Worker reaches the application gateway. Incoming identity, forwarding and proxy headers and Access cookies are stripped. Mutations must carry the exact private origin.

`PRIVATE_ORIGIN` is the exact private `http://` or `https://` origin without a trailing slash; `ACCESS_TEAM_DOMAIN` is the host of the Cloudflare Access team; and `ACCESS_AUD` is the private application's audience. The Worker has a 15-second deadline until response headers, bounds requests to 1 MiB, and streams responses with a 15-second idle timeout. Invalid or expired assertions require sign-in, identity lookup or key-service failures return 503, and timeouts before response headers return 504. A response that stalls after its headers have been sent is cancelled and ends with a stream error. Only GET/HEAD to `/cdn-cgi/access/login` and `/cdn-cgi/access/logout` can continue to the original upstream. A GET accepting HTML without a valid identity or assertion redirects to the local Access login path; API requests return 401. The redirect and natural expiry recovery must be validated against the actual private Access application. No token, cookie, or claim is logged.

Use a compatibility date of 2026-11-25 or later to enable ReadableStream constructors. Gateway Forward is a public beta. HTTPS requires Gateway TLS decryption, matching Workers VPC traffic is dropped, and CONNECT, upgrades, and WebSockets bypass the Worker. Configure separate network and Access controls to prevent bypass and ensure the Gatus origin and nonidentity probes do not match the Forward rule. See [Gateway Forward](https://developers.cloudflare.com/cloudflare-one/traffic-controls/integrate-workers/forward-traffic/) and [Gateway context](https://developers.cloudflare.com/cloudflare-one/traffic-controls/integrate-workers/available-context/).

Before production use, test the exact artifact on an isolated private hostname with the intended Access application, audience, policy and Gateway configuration: initial login, expired-session recovery, logout, denied users, forged assertions, role authorization, fallback snapshot and assets, Gatus VPC exclusion, protocol bypasses, and rollback. Local tests cannot establish Gateway policy or private Access behavior. Keep the original Gatus route, checks, and alerting intact until these checks pass.

For rollback, disable the Forward rule before removing the Worker. Remove or disable any newly added production Access application before declaring legacy Gatus restored, and verify the original private route, checks, health, and alerts. Do not alter shared policies.

Run local checks with `npx tsc -p apps/gateway/private-bridge` and `node --import tsx --test apps/gateway/private-bridge/*.test.mts`. The workerd tests require permission to open a loopback listener.
